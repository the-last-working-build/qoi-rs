# Benchmark methodology

## Objective

Compare the pinned C QOI implementation and the Rust port under equivalent
in-memory encode and decode workloads.

## Environment

- Commit: recorded in `bench/results/results.txt` for each run
- Branch and tree state: recorded in `bench/results/results.txt`
- Operating system: recorded in `bench/results/results.txt`
- CPU: recorded in `bench/results/results.txt`
- Rust compiler: recorded in `bench/results/results.txt`
- C compiler: recorded in `bench/results/results.txt`
- Rust optimization: `cargo run --release --manifest-path bench/Cargo.toml`
- C optimization: benchmark-only wrapper compiled with `cc`, `-O3` and `NDEBUG`

## Fixtures

- `flat-rgba`: 1024x1024 RGBA, every pixel is `[24, 80, 160, 255]`.
- `gradient-rgb`: 1024x1024 RGB, each pixel is `[x + y, x + 2y, 2x + y]`
  modulo 256.
- `noise-rgba`: 1024x1024 RGBA, generated by a deterministic xorshift64*
  stream seeded with `0x515f4f495f525553`.

## Operations

Encoding begins from identical raw pixel buffers.

Decoding begins from the same byte-for-byte QOI stream produced by the pinned C
encoder.

Allocation and codec work are included. Fixture generation and file I/O are
excluded.

## Procedure

- 10 warm-up iterations
- 100 measured iterations per fixture and operation
- monotonic high-resolution clock
- results reported as median nanoseconds and throughput
- output bytes are consumed to prevent dead-code elimination

## Limitations

The benchmark is a focused comparison on one machine, compiler version and
fixture set. It is not a universal performance claim.
